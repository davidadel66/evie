# Keep semantic-memory truth in the Kernel

The Kernel owns accepted Semantic Operations, scope and authority enforcement,
provenance, lifecycle transitions, and deterministic replay because those are
durability and safety guarantees. A compiled First-party Plugin may contribute
session-bound Memory Capabilities selected by Agent Presets and recorded in
Composition Receipts, but disabling or replacing that plugin cannot delete,
reinterpret, or become the authority for stored memory. A general Memory
Provider seam remains deferred until context composition has a concrete need
for multiple meaningful adapters. The first-party Memory Plugin is therefore a
tool adapter over a narrow Kernel-owned semantic interface, not the owner of a
database handle, local inspection, or replay.
