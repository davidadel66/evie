# Memory Stage 5: reference interpretation (#161)

This implements #161 after committed and verified #160. The configured production reader interprets references using the request, bounded earlier discussion, accepted compaction continuity, and eligible original memory. There is no separate interpretation model, local interpretation-model setup, hidden-reasoning persistence, remote fallback, or new production dependency.

Automatic recall ranks lexical relevance first, then mean inverse frequency within the bounded earlier-root window, then earlier position. A distinct earlier recipient can survive repeated debugging discussion without a kinship, gift, city, or name dictionary. Multiple identities remain hypotheses; their count never forces clarification. The existing reader may use targeted existing tools and asks one focused question before person-specific recommendations only when remaining ambiguity materially changes the answer. Dynamic reading guidance applies only to automatic interpretation; the stable system prefix is unchanged.

The planner examines at most 512 current UTF-8 bytes, sixteen earlier owner roots of at most 384 bytes each, and 512 bytes of accepted continuity. It selects at most two earlier roots/five terms each, sixteen current terms and six continuity terms, forming at most thirty-two terms/1,024 bytes. Up to two explicit UUID/opaque selectors of at most 128 bytes each use separate existing scoped exact/alias searches. Both ordinary searches still run, so an incidental error code cannot suppress current context. At most four automatic searches consume the same eight-call, 36-KiB, three-second-work ledger; they never reset it.

A bounded identity match exposes the accepted Entity/Alias mapping and alias value to the reader. Its immutable request reference contains IDs and the original Source Link locator/hash, never alias value or query text. The Kernel checks Entity/Alias lifecycle at the original read and currently, allowed alias scope, the alias's accepted operation/source event, exact Source Link provenance and current source eligibility. A retired alias or restricted source removes its mapping while independently eligible Claims remain available. At most two mappings per Claim and three candidate origin Source Links bound this work; limits conservatively omit unsupported mappings. Interpretation never changes identity, acceptance or scope authority.

The `bounded-reference-lexical-v2` receipt retains content-free version/status and measured current, examined-earlier, selected-earlier, continuity, lexical-query and exact-selector byte/count bounds. It stores no query/summary contents or hidden reasoning. Compaction is interpretation context, never an original source.

The primary seam is a complete public `Session.Send` with real SQLite and a scripted provider. Regressions cover earlier recipients after repeated topic noise; paired mother/sister and misleading recent mentions; original sources after public compaction plus twenty topics; exact UUIDs/aliases and misleading error codes; no evidence; other-project/raw-Global exclusions; retirement/retraction; targeted existing reads; bounded inputs; and independent alias-origin source restriction across reopen. The first recipient and exact-UUID tracers failed before planner changes; the source-backed alias mapping failed before Kernel support.

Nine pinned development cases also run the existing production Default reader from request one. Configuration, source/binary hashes, discovered canonical model, rubric and cases were frozen before each run. v1 retains two manual failures (7/9): premature recommendations during compacted ambiguity and an unresolved opaque alias despite the right preference. v2 passes nine automated and nine manual cases under the unchanged semantic rubric after dynamic reference guidance and transparent accepted alias support. Every raw request/response remains under `cmd/evie/docs/fixtures/memory-stage5-reference-reader/`. These are development results, not #167/#168 held-out results.

v2 used nine actual model calls in 26.34 seconds, with 27,759 input tokens and 393 output tokens. Complete requests ranged from 9,936 to 18,235 serialized bytes, with at most four evidence items. Observed interpretation maxima: 70 current bytes; sixteen examined roots/528 bytes; two selected roots/174 bytes; 374 continuity bytes; 88 lexical-query bytes; and one exact selector/36 bytes. A separate complete-turn boundary fixture reaches exactly 512 current bytes, sixteen examined roots/6,144 bytes, two selected roots/768 bytes, two exact selectors/14 bytes and a 72-byte lexical query. Measurements and the unchanged manual rubric are retained with the raw results.
