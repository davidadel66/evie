## Parent

[Subagents: Preset-composed foreground research with Kernel supervision (#155)](https://github.com/davidadel66/evie/issues/155)

## What to build

Build the complete ordinary foreground path through the real delegation capability, Kernel supervisor, child conversation, durable execution attempt, and parent result. Use the existing provider role and agent runtime; keep the compiled Subagents Plugin absent from production registration and standard-preset exposure until the later rollout ticket.

The deterministic composed acceptance assembly must use the production adapter and supervisor, substituting only external model/Web execution. This ticket owns atomic admission, ordinary success/failure, finite bounds, optional Task association, and idempotent reuse. Adversarial ownership races and restart reconciliation have separate tickets.

## Acceptance criteria

- [ ] A scripted parent invokes the selected delegation capability; a real child session researches through the restricted preset; a bounded persisted finding returns through the parent's normal conversation flow and the parent answers.
- [ ] Admission accepts only the bounded objective, optional selected context, optional Task identity, and idempotency key. Runtime-supplied parent session, committed invocation, Context Scope, and current parent fence are authoritative; the model cannot supply broader authority.
- [ ] Before any provider call, one SQLite transaction admits the execution attempt with its canonical request digest, parent invocation/ownership identity, child session, inherited scope, pinned composition/policy, and optional Task association. Failure creates no runnable orphan.
- [ ] Eligible Global/project parents can admit research only when the child capabilities fit the parent's pinned composition and current resource ceilings. Workspace admission fails visibly while reviewed preset allowances are unavailable and never substitutes Global scope.
- [ ] Execution status is distinct from Session and Task status and covers admitted, running, succeeded, failed, cancelled, and interrupted attempts. This ticket implements the ordinary admitted/running/success/failure flow and establishes the durable terminal contract used by later lifecycle work.
- [ ] The child uses its own history and turn ownership, the approved isolated context policy, and the parent's resolved model/provider configuration. It never reacquires the parent session lock or writes directly into parent history.
- [ ] Enforce depth one, one active child per parent turn, finite runtime capacity, deadline, total conversational-plus-compaction model calls, input/output context, and result-size limits from validated Kernel policy. Missing or unbounded policies reject admission; model arguments cannot raise limits.
- [ ] A supplied Task is validated using the parent's current Task authority and scope, then recorded only as an association. Delegation creates no Task, grants, focus, or claims and does not change Task status. Omission works without Task machinery.
- [ ] Parent-session identity plus idempotency key identifies one attempt. Concurrent matching requests start only one child; identical calls return/join that attempt within caller bounds; changed arguments conflict. Other parents cannot inspect or attach to it.
- [ ] An authorized committed final child assistant event is authoritative success. Persist the bounded result projection before parent delivery, and retain its event linkage so later cancellation or restart can preserve accepted completion even if that projection was not yet written.
- [ ] Results contain execution/child identities, terminal status, findings, evidence references, limitations, and available usage. Unknown usage stays unknown. Provider and policy failures are explicit; reasoning and the full child transcript are not returned as findings.
- [ ] Child streaming never appears as the primary agent's own public response. Parent delivery uses the existing invocation/result presentation and the parent's current persistence fence.
- [ ] The foreground path has baseline context cancellation and bounded resource cleanup. No user/configuration switch can enable production delegation before the lifecycle, recovery, and rollout tickets complete.
- [ ] Verify through the approved parent-to-child-to-parent conversation seam with deterministic external execution and real SQLite, including ordinary failure, request limits, atomic rollback, concurrent duplicate admission, changed-key arguments, and excluded capability execution. Run full repository verification and focused race checks.
