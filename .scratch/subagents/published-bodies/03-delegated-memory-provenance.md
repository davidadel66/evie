## What to build

Make existing delegated session lineage authoritative when determining eligible memory evidence. A parent-authored assignment must not become an owner assertion simply because the conversation transport stores it in a user-role message.

Exercise the existing live and historical compilation interfaces against real persisted delegated sessions. This is a complete source-eligibility outcome and requires neither the new research preset nor a running Subagents Plugin.

## Acceptance criteria

- [ ] Persisted delegated sessions are mechanically excluded from live automatic compilation and explicit historical compilation before source extraction. Session parent lineage, not prompt text, determines eligibility.
- [ ] Source revalidation before candidate publication also excludes delegated history, so a staged or retried selection cannot bypass the rule after initial admission.
- [ ] Delegated assignments and findings cannot serve as owner-assertion support through another memory source-selection or evidence-admission path.
- [ ] A delegation result recorded in the parent remains agent-produced capability output with delegated provenance. It does not become owner testimony or a newly approved memory-observation source.
- [ ] Eligible primary-session owner assertions and existing approved observation contracts retain their behavior. Existing accepted memories are not rewritten and no new compiler implementation is introduced.
- [ ] Deterministic acceptance covers live activation, explicit historical selection, revalidation/publication, and parent-side results using real SQLite and an extractor spy that proves forbidden sources never reach extraction.
- [ ] Use the existing delegated-session and compiler evidence-contract fixtures. Run focused eligibility/compiler checks and the full repository verification required for code changes.
